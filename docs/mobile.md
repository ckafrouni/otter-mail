# The iPhone app

`apps/mobile` is Otter Mail for iPhone: an Expo app set up like Otter Code Mobile (Expo 57,
React Native 0.86, uniwind for Tailwind classNames, react-navigation's static native stacks with
Liquid Glass headers, SF Symbols, DM Sans).

Where the desktop app keeps Gmail in its Electron main process, the phone has no main process and
no server: it signs in to Google itself and calls the Gmail API directly. It is local-first the
same way: screens render from an expo-sqlite cache (`src/state/db.ts`) and sync
(`src/state/sync.ts`) catches the cache up; actions (`src/state/actions.ts`) change the cache first
and roll back if Gmail refuses. Gmail types come from `@otter-mail/contracts/gmail`, shared with
the desktop.

What it does today: several accounts, All Inboxes, per-account Inbox / Starred / Sent / Drafts /
All Mail / Trash, pull to refresh and paging, Gmail search, swipe to archive or trash and to mark
read, threads with HTML mail, star / archive / trash / mark unread, and plain-text
compose, reply, reply all and forward.

## Prerequisites

- Full Xcode with an iOS simulator, and CocoaPods (`brew install cocoapods`).
- An OAuth client of type **iOS** in the `otter-mail` Google Cloud project
  (https://console.cloud.google.com/auth/clients?project=otter-mail), with bundle ID
  `dev.otterware.mail.dev` for development builds (`dev.otterware.mail` for release builds, which
  need a client of their own). Put its client ID in `.env.local`:

  ```sh
  OTTER_MAIL_GOOGLE_IOS_CLIENT_ID=1234-abcd.apps.googleusercontent.com
  ```

  iOS clients have no secret: sign-in uses PKCE, and Google redirects to the client ID's reversed
  form, which `app.config.ts` registers as a URL scheme. Rebuild after changing it.

## Running

The app uses native modules, so Expo Go won't do; it runs in its own development build.

```sh
pnpm ios          # prebuild + build + install into the booted simulator, then start Metro
pnpm dev:mobile   # later: just Metro, for an already installed development build
```

From `apps/mobile`, `pnpm ios:prod` builds a self-contained Release app, and `eas build` profiles
(`eas.json`) exist for device and store builds once an EAS project is linked.

Screens have deep links (`ottermail://thread/<account>/<thread>`, `…/settings`, `…/compose`;
`ottermail-dev://` for development builds), handy with `xcrun simctl openurl booted <url>`.

Development builds are "Otter Mail Dev" (`dev.otterware.mail.dev`, the blueprint icon) and install
next to release builds, each with its own cache and Keychain entries. `ios/` is generated by
`expo prebuild` and gitignored; change `app.config.ts` instead.

## Where things are

| Path              | What                                                                      |
| ----------------- | ------------------------------------------------------------------------- |
| `app.config.ts`   | Expo config: variants, icons, fonts, the Google redirect scheme.          |
| `global.css`      | Theme tokens (Otter Code's palette, light and dark) and the type scale.   |
| `src/Stack.tsx`   | The navigator: Mailboxes → Mailbox → Thread, Compose and Settings modals. |
| `src/gmail/`      | OAuth, the Gmail REST client, MIME reading/writing.                       |
| `src/state/`      | SQLite cache, sync, actions, accounts, appearance.                        |
| `src/features/`   | One folder per screen.                                                    |
| `src/components/` | Shared UI: text, symbols, grouped lists, avatars, buttons.                |
